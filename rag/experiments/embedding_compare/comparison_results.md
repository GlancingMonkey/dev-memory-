E5는 이번 10개 질문 모두 정답을 1위에 올렸다. 설치와 CPU 로컬 추론이 정상적으로 동작했다.
Qwen도 10개 질문 모두 정답을 1위로 찾았으며, 한국어 문서 2문제와 한국어·영어 코드 각 4문제에서 E5와 동일한 Hit@1·Hit@3·MRR을 기록했다. 전체 MRR은 두 모델 모두 1.00이다.
Qwen 질문 p50은 337.45ms로 E5의 약 6.62배였다. E5의 문서 embedding 처리량은 Qwen의 약 4.61배였다. 이번 데이터에서 Qwen의 검색 정확도 개선은 관찰되지 않았으므로 E5를 1차 후보로 선택한다.
샘플이 작고 질문이 구체적이므로 이 점수만으로 실제 프로젝트의 검색 품질을 확정할 수 없다.
BGE는 10개 중 9개 질문의 정답을 1위에 올렸고, 10개 모두 상위 3개 안에 정답을 포함했다. 전체 MRR은 0.95다.
한국어 TypeScript 저장 질문에서는 `ts_load`(읽기)를 1위, 정답인 `ts_save`(저장)를 2위에 올렸다. 같은 의미의 영어 질문에서는 정답을 1위로 찾았다.
해당 한국어 질문의 두 점수는 0.60202와 0.59990으로 차이가 작다. 한국어 입력에서 저장/읽기 의미를 구분하는 추가 질문을 시험할 근거이며, 한 문제로 언어 성능 전반을 판단하지 않는다.
이번 CPU 측정에서 BGE의 질문 p50은 E5의 약 3.32배이며 문서 처리량도 더 낮다. 같은 데이터 해시·장치·정밀도·반복 설정을 확인했다. 다른 시점에 실행했으므로 시스템 부하 차이는 통제하지 않았다.
차원은 E5 768, BGE와 Qwen 1024다. 벡터 원소 수 기준으로 E5가 25% 적다. 실제 DB 저장 크기와 인덱스 비용은 측정하지 않았다.

## 선택의 적용 범위

이번 선택은 512토큰 이하의 짧은 문서·코드와 구체적인 질문을 사용하는 CPU 검색의 기준선이다.
코드 검색 질문은 한국어 4개뿐이며 질문 하나가 25%p에 해당한다. E5와 Qwen의 동점은 이 작은 데이터에서의 동점이며, 전체 코드 검색 성능이 같다는 뜻은 아니다.
모델별 tokenizer와 필요한 prefix/instruction이 달라 처리하는 토큰 수는 다르다. 동일 512토큰 상한 안에서 각 모델에 필요한 입력 규칙을 적용한 전체 질문 encoding 시간을 비교했다.
질문 시간은 서로 다른 10개 질문을 5회 반복한 50개 값으로, 운영 동시 접속이나 대규모 데이터 검색 성능은 평가하지 않았다.
BGE·Qwen의 긴 입력 능력, GPU 실행, peak RAM, 벡터 인덱스 성능, 답변 품질도 이 실험의 측정 범위 밖이다.

다음 품질 검증을 진행할 때는 실제 프로젝트 함수·문서와 한국어 질문 20~30개로 같은 비교를 수행한다. 저장/읽기·수정/삭제·동기/비동기·예외 처리처럼 비슷한 오답 후보를 추가하고 정답을 모델 실행 전에 정한다.
이 추가 검증 전에는 E5를 Semantic Search의 기본 후보로 두고 Qwen을 비교 후보로 남긴다.
