# Code Memory Extension

처음 사용한다면 [사진으로 따라 하는 사용 가이드](../docs/USER_GUIDE.md)를 확인하세요. 코드 저장부터 검색·필터·AI 답변까지 실제 밝은 테마 화면으로 설명합니다.

VS Code에서 선택한 코드·메타데이터를 저장하고, Backend의 실제 검색 결과를 표시하는 TypeScript Extension이다.

## 현재 기능

| 흐름 | 제공 기능 |
|---|---|
| 저장 | 코드 선택·함수 범위 인식, 메타데이터 수집, 중복 실행 방지, 원문 저장·검색 준비 상태 구분 |
| 검색 | 자연어 검색, 순위·ID·유사도·코드 위치, 최근 검색·결과 복원, 간단히 보기·검색 범위(프로젝트·언어, 서버에서 거름) |
| 코드 활용 | 원본 열기, 복사·들여쓰기 맞춤 삽입, 선택 코드와 비교, 비슷한 코드 찾기 |
| 사용 안내 | 실제 서버·mock 표시, 연결 확인, 저장 기록, 제한 시간 설정, 시작하기 안내 |

함수 범위·이름은 언어 확장이 제공하는 코드 구조를 우선 사용하며 상황에 따라 직접 선택·수정이 필요하다. 아래 사용법에서 조건과 설정을 확인한다.

저장·검색·AI 질문의 요청과 응답은 [API_CONTRACT.md](../API_CONTRACT.md)를 따른다. Backend는 원문을 먼저 커밋한 뒤 자동 Embedding과 벡터·상태 저장까지 기다려 응답한다. 저장과 일반 검색은 LLM을 호출하지 않으며, AI 질문(`POST /ask`)을 실행할 때 검색한 코드로 RAG 답변을 만든다.

## 실행 전 준비

이 가이드는 **같은 PC에서 Backend는 Dev Container, Extension은 Windows 로컬**로 실행한 검증 방법이다.

- Backend의 /health와 /docs에 Windows 브라우저로 접속할 수 있어야 한다.
- 실제 DB에 embedding vector(768), embedding_status, embedding_error가 필요하다. [개발 가이드](../docs/DEVELOPMENT.md)에서 스키마와 Backend의 E5 warmup을 확인한다. 새 저장 응답이 ready이면 검색할 수 있고, 기존 미처리·실패 행은 [재처리 CLI](../rag/README.md)로 확인한다.
- Windows에도 Node.js·npm이 필요하다. Dev Container의 Node 설치와 Windows 설치는 별개다.
- package.json의 VS Code 요구 범위는 `^1.138.0`이다. [2026-11-05 검증](../docs/INTEGRATION_TEST_2026-11-05.md)에서는 VS Code 1.145.0 x64, Node v24.20.0, npm 11.19.0을 사용했다.

## 빌드

아래 경로는 검증 때 사용한 예시다. 본인의 저장소 경로로 바꾼다. Windows PowerShell에서 실행한다.

```powershell
cd C:\dev\capstone-rag\extension
npm.cmd ci
npm.cmd run compile
```

compile은 TypeScript 검사 → ESLint → esbuild 번들링 순서다. 각 단계가 성공한 뒤 다음 작업을 진행한다.

## 개발 호스트 열기

테스트할 프로젝트 폴더를 먼저 준비한다. `C:\dev\mvp-save-test`는 별도 로컬 테스트 폴더 예시이며 저장소에 포함된 폴더가 아니다.

빌드가 끝난 뒤 Windows PowerShell에서 실행한다.

```powershell
code.cmd --new-window --extensionDevelopmentPath="C:\dev\capstone-rag\extension" "C:\dev\mvp-save-test"
```

새로 열린 **확장 개발 호스트**에서 테스트한다. 같은 Extension을 다시 빌드했다면 개발 호스트를 다시 로드하여 변경을 반영한다.

F5의 Run Extension을 사용하는 경우에는 이 extension 폴더 자체를 VS Code에서 열고 [.vscode/extensions.json](.vscode/extensions.json)의 권장 확장을 확인한다. watch 작업의 `$esbuild-watch`는 권장 esbuild problem matcher 확장을 사용한다. 위 명령어 실행 방식은 사전 빌드한 dist를 사용한다.

## 실제 API 설정

새로 열린 **확장 개발 호스트**에서 Ctrl+,를 누르고 **Workspace / 작업 영역** 탭에서 codeMemory를 검색한다. Backend를 연 Dev Container 창의 설정과 구분한다. 설정 변경 후 개발 호스트 하단 상태 표시줄의 실제 모드·주소가 원하는 값인지 확인한다.

| 설정 | 기본값 | 실제 연동 테스트 값 |
|---|---|---|
| codeMemory.mock | true | false |
| codeMemory.apiUrl | http://localhost:8000 | http://127.0.0.1:8000 또는 실제 전달 주소 |
| codeMemory.searchLimit | 10 | 검색 결과 최대 개수 (API 계약 범위 1~20) |
| codeMemory.confirmFunctionName | false | true면 저장 전에 함수 이름 입력창이 뜬다 |
| codeMemory.saveTimeoutSeconds | 10 | 저장 요청 제한 시간(초). 실제 측정 후 팀이 정한다 |
| codeMemory.searchTimeoutSeconds | 10 | 검색 요청 제한 시간(초) |
| codeMemory.askTimeoutSeconds | 45 | AI 질문 제한 시간(초). 넘어도 자동 재전송 안 함 |
| codeMemory.askOnQuestionMark | true | 끝에 `?`면 Enter로 AI 질문. 끄면 Enter는 항상 검색 |

Mock이 true이면 서버를 호출하지 않는다. 검색은 질문과 관계없이 고정 샘플 3개를 표시하고 저장은 가짜 id를 반환한다. 실제 검증에서는 false로 설정한다.

현재 모드는 VS Code 아래 상태 표시줄에 항상 보인다.

| 표시 | 뜻 |
|---|---|
| `Code Memory: mock` (노란 배경) | mock. 서버를 호출하지 않음 |
| `✓ Code Memory: 127.0.0.1:8000` | 실제 서버. `GET /health` 응답 정상 |
| `✕ Code Memory: 127.0.0.1:8000 연결 안 됨` (빨간 배경) | 실제 서버. `/health` 확인 실패 — 서버 실행·주소·포트 전달 확인 |

실제 서버 모드에서는 30초마다, 그리고 설정이 바뀔 때 `/health`를 다시 확인한다. `/health` 정상은 서버가 켜져 있다는 뜻이며 DB 저장 성공까지 뜻하지는 않는다.

상태 표시줄을 누르면(또는 명령 팔레트의 **Code Memory: 모드 바꾸기**) mock / 실제 서버 전환, 서버 주소 바꾸기, 연결 다시 확인, 설정 열기를 고를 수 있다. mock일 때는 검색 패널 위에도 노란 MOCK 안내가 뜬다.

## 저장

1. 개발 호스트에서 프로젝트 폴더를 연다.
2. 파일을 프로젝트 안에 저장하고 코드 범위를 선택한다. 선택이 없으면 언어 확장의 코드 구조에서 커서를 감싼 함수를 찾아 전체 범위를 선택한다. 함수 범위를 인식하지 못하면 직접 코드를 선택한다.
3. 명령 팔레트의 **Code Memory: 코드 저장**, 우클릭 메뉴 또는 Ctrl+Alt+S를 실행한다.
4. 오른쪽 아래에 `Code Memory: 저장 중…`이 뜬다. 응답이 올 때까지 저장 명령을 다시 실행해도 요청을 보내지 않는다.
5. 출력 → Code Memory에서 POST 주소·HTTP 상태·실제 반환 id를 확인한다.
6. DB에서 그 id를 조회해 코드 원문을 포함한 7개 저장 필드를 대조한다.
7. ready 응답의 **검색에서 확인**을 누르면 검색 패널이 열리고 함수 이름(없으면 파일 이름)으로 바로 검색한다. failed 또는 상태 확인 불가 응답은 경고와 저장된 ID를 안내한다. 검색 패널이 열려 있으면 패널 아래에도 결과 알림이 잠깐 뜬다.

### 함수 이름

함수 이름은 VS Code가 알고 있는 코드 구조(개요 창에 나오는 기호)에서 선택 시작 줄을 감싸는 가장 안쪽 함수 이름을 쓴다. 함수가 없으면 클래스 이름, 둘 다 없으면 `null`이다. 그 언어의 코드 구조를 못 받으면(언어 확장 없음 등) 예전 정규식 방식(python·typescript·javascript·java)으로 찾는다.

### 검색 준비 상태

확정된 필드는 id, message, embedding_status, embedding_error다. message는 원문 저장 완료 시 `snippet saved`다. 과거 별칭 필드는 공식 필드를 대신하지 않는다.

| HTTP / 상태 | 알림 | 저장 기록 |
|---|---|---|
| 200 / ready | 저장 완료 · 검색 준비 완료 | ID 유지 · 검색 준비됨 |
| 200 / failed | 원문 저장 완료 · 검색 준비 실패 | ID 유지 · 검색 준비 실패 |
| 503 / 저장된 ID + null | 원문 저장 완료 · 검색 준비 상태 확인 불가 | ID 유지 · 검색 준비 확인 필요 |
| 503 / detail만 있음, 시간 초과, 응답 확인 불가 | 저장 여부 확인 필요 · 재전송 전 서버 로그·DB 확인 | 저장 여부 확인 필요 |
| 422 | 요청 필드·입력값 검증 오류 | 실패 |

HTTP 503에 id와 message가 있고 embedding_status=null, embedding_error=embedding_storage_failed이면 원문은 저장된 상태다. ID를 보존하고 해당 행부터 확인한다. null은 API가 최종 상태를 확인하지 못했다는 뜻이며 DB의 새 상태 값이 아니다.

DB의 pending은 임베딩 미처리 상태다. 과거 저장 기록에 pending이 있으면 `임베딩 미처리`로 표시하며 백그라운드 처리 중이라고 안내하지 않는다. 현재 POST의 정상 완료 응답 상태는 ready 또는 failed다.

입력 한도 초과의 failed/embedding_input_invalid는 같은 입력을 그대로 재처리하지 않는다. 생성·저장 실패는 기존 ID의 원문과 상태를 확인한 뒤 재처리 CLI를 사용한다. 같은 POST를 자동 재전송하지 않는다.

### 저장 전 확인

`codeMemory.confirmFunctionName`을 켜면 저장 직전에 자동으로 찾은 함수 이름이 입력창에 뜬다. 고치거나 그대로 Enter, 비우면 이름 없이(`null`) 저장, Esc는 저장 취소다. 정규식 추출이 틀렸을 때 쓴다.

저장할 때마다 검색 패널 아래 **저장 기록**에 한 줄씩 남는다 (최대 20개, 폴더별). 원문 저장이 확인된 경우 실제 ID와 검색 준비 상태를 유지한다. mock, 요청 실패, 저장 여부 확인 필요도 구분한다. 기록을 누르면 함수 이름으로 검색하며 실패·확인 불가 상태만으로 검색 가능하다고 판단하지 않는다.

저장 요청은 `codeMemory.saveTimeoutSeconds`(기본 10초) 안에 응답이 없으면 `응답 시간 초과`로 안내한다. 출력 패널의 POST 줄 끝과 저장 기록에 실제로 걸린 시간이 남으니, 제한 시간을 정할 때 이 값을 쓴다. 이때 서버에는 저장됐을 수 있으므로 다시 저장하지 말고 서버 로그·DB를 먼저 확인한다. 시간 초과 뒤 자동으로 다시 보내지 않는다.

아직 디스크에 저장하지 않은 새 파일(Untitled), 프로젝트 밖 파일, 함수 범위도 자동 인식할 수 없는 빈 선택, 공백뿐인 코드는 안내 후 저장을 중단한다. 원본 절대 경로는 Extension 내부에서 사용하고 요청에는 기존 7개 필드만 넣는다.

## 검색과 코드 사용

왼쪽 Code Memory 검색창에 자연어를 입력한다. 실제 요청은 GET /search?q=...&limit=10이고 결과는 Backend 순서대로 표시한다.

- 카드는 `순위 · 함수 이름 · 유사도`, `파일 : 시작–끝 줄`, `프로젝트 · 언어 · id` 순서로 보인다. 순위와 id는 Swagger 결과와 대조할 때 쓴다.
- 유사도는 score(코사인 유사도, -1~1)를 소수점으로 표시한다. 클수록 유사하며 정답 확률이나 정확도 퍼센트가 아니다.
- 코드는 실제 줄 번호(start_line부터)와 함께 보이고, 6줄이 넘으면 접힌다. **N줄 전체 보기**로 펼친다.
- **원본 열기** 또는 파일 이름 링크: 이 PC에서 연 프로젝트의 위치를 기억하므로, 다른 프로젝트에서 검색해도 원본 파일만 바로 열 수 있다. 이전 프로젝트 폴더를 다시 열 필요가 없다.
  - 위치는 VS Code의 로컬 `globalState`에 보관한다. 절대 경로를 Backend·DB로 보내거나 Git·설정 파일에 넣지 않는다. 로컬과 원격 Extension 환경의 기록은 구분한다.
  - 위치를 모르는 예전 코드나 다른 PC의 코드에는 **원본 위치 연결**이 표시된다. 한 번 프로젝트 폴더를 선택하면 이후에는 기억한 위치를 사용한다. 폴더를 현재 작업 영역에 추가하지 않는다.
  - 같은 이름의 프로젝트를 여러 위치에서 사용하면 임의로 고르지 않는다. 사용자가 명시적으로 연결한 위치를 우선한다.
  - 프로젝트 폴더를 옮겼다면 새 위치를 다시 연결한다. 저장한 코드와 다르면 연결 전에 확인한다. 명령 팔레트의 **Code Memory: 원본 프로젝트 위치 연결**로도 등록할 수 있다. 파일 자체의 이름·상대 경로가 바뀌었다면 현재 파일에서 다시 저장해야 한다.
- **삽입**: 현재 편집기의 선택 영역을 결과 코드로 바꾼다. 결과 코드의 공통 들여쓰기를 걷어내고 커서 위치의 들여쓰기에 맞춰 넣는다. 검증할 때는 새 빈 편집기를 사용한다.
- **비교**: 왼쪽에 지금 에디터에서 선택한 코드(선택이 없으면 마지막으로 **비슷한 코드 찾기**에 쓴 코드), 오른쪽에 저장된 코드를 VS Code 비교 화면으로 연다. 읽기 전용이라 닫을 때 저장을 묻지 않는다.
- 코드에는 문법 색이 칠해진다 (문자열·주석·숫자·키워드·함수·타입·데코레이터). 여러 줄 주석·문자열도 이어서 칠한다. 에디터만큼 정확하지는 않다.
- **복사**: 결과 코드 원문을 클립보드에 복사한다. 버튼이 잠깐 `복사됨 ✓`으로 바뀐다.
- 검색 응답을 기다리는 동안 검색 버튼이 잠긴다.
- 검색창을 누르면 최근 검색어 5개가 펼쳐진다. ↑↓로 고르고 Enter, Esc로 닫는다. **지우기**로 비운다.
- 마지막 검색어와 결과는 폴더(워크스페이스)별로 저장돼, 다시 열면 `지난 검색`으로 복원된다.
- **Ctrl+Alt+F** 또는 명령 팔레트의 **Code Memory: 검색창 열기**로 검색 패널을 열고 검색창에 커서를 둔다.
- 검색창과 요약줄은 스크롤해도 위에 고정된다.
- 요약줄의 **자세히 / 간단히**: 간단히는 결과를 한 줄씩(순위·이름·위치·유사도) 보여준다. 줄을 누르면 원본 열기. 선택은 기억된다.
- **검색 범위** (#38 #39 #40): 검색창 아래 `프로젝트 전체 ▾` `언어 전체 ▾` 칩. 고르면 `GET /search` 에 `project`·`language` 를 같이 보내서 **DB 에서 먼저 거르고** Top-K 를 뽑는다 (받은 결과 안에서 거르는 게 아님).
  - 목록은 `GET /filters` (DB 에 있는 프로젝트·언어와 코드 수). 지금 열린 폴더는 맨 위에 "열린 폴더". 목록에 없으면 이름을 직접 입력할 수 있다.
  - 고르면 마지막 검색어로 바로 다시 검색. 칩의 ✕ 로 하나씩, **모두 해제**로 전부 해제. 늦게 온 이전 결과는 버린다. 고른 범위는 다시 열어도 유지된다.
  - 범위 때문에 0개면 "이 범위에는 결과가 없어요" + 조건 풀기 버튼.
  - 서버가 응답에 적용한 조건(`filters`)을 돌려주지 않으면(옛 서버) **화면에서만 거름** 경고를 띄우고 받은 결과 안에서만 거른다.
  - AI 질문(`/ask`)에는 범위를 보내지 않는다. 범위가 걸려 있으면 답변에 "범위 무시 · 전체 DB" 표시.
- 요약줄의 **기록 복사**: 질문·모드(mock/실제 서버 주소)·시각·범위와 결과(순위·id·함수·위치·유사도)를 마크다운 표로 복사한다.
- 요약줄의 **×**: 결과를 지우고 처음 화면(예시 질문)으로 돌아간다. 지난 검색 복원도 지워진다.
- 결과가 없으면 **다른 말로 검색** / **모드 바꾸기** 버튼, 오류가 나면 **다시 시도** 버튼이 나온다. 시간 초과는 노란색, 연결·서버 오류는 빨간색이다.
- 결과 카드의 언어 앞 색 점은 언어별 색이다 (python 파랑, typescript 하늘색 등).
- 키보드: 검색창에서 ↓ 로 결과 카드로 이동한다. 카드에서 ↑↓ 이동, Enter 원본 열기, C 복사, I 삽입, D 비교, Esc 검색창.
- **비슷한 코드 찾기**: 에디터에서 코드를 선택하고 우클릭 → **Code Memory: 비슷한 코드 찾기**. 선택한 코드를 그대로 질문으로 보내 기존 `GET /search`로 검색한다 (줄바꿈은 공백으로, 1000자까지). 코드를 질문 자리에 넣는 방식이라 자연어 질문보다 결과 품질이 낮을 수 있다.

DB에 코드와 경로가 저장되어도 PC에 원본 파일이 자동으로 생성되지는 않는다.

## AI 질문 (이슈 #44)

저장된 코드를 근거로 AI 답변과 출처를 받는다. **일반 검색이 기본**이고, AI 질문은 사람이 실행할 때만 보낸다. 입력하거나 탭을 옮기는 것만으로는 요청이 나가지 않는다. 검색인지 질문인지는 **LLM 없이 규칙으로만** 판단한다 (검색할 때 LLM 호출 0회).

| 입력 | Enter |
|---|---|
| `정렬 함수` | 일반 검색 |
| `add 함수는 뭘 반환해?` — **끝에 `?`** (전각 `？` 포함) | **AI 질문**. 입력하는 동안 돋보기가 ✦로, 버튼이 **✦ 묻기**로, 테두리가 AI 색으로 바뀐다 |
| `a ? b : c 삼항 연산자` — 중간에만 `?` | 일반 검색 (코드 검색어에 `?`가 섞이는 경우) |
| `두 숫자 더하는 함수 동작 설명해줘` — `?` 없이 질문처럼 생김 | 일반 검색 + 결과 위에 **"질문처럼 보여요 — AI에게 물어볼까요?"** 한 줄. 누를 때만 AI 질문 |

| 단축키 | 동작 |
|---|---|
| Ctrl+Enter | 끝에 `?`가 없어도 항상 AI 질문 |
| Shift+Enter | 끝에 `?`가 있어도 항상 일반 검색 |

- 처음 화면의 예시가 **검색 예시**와 **질문 예시**(끝에 `?`, 파란 테두리)로 나뉜다. 누르면 각각 검색 / AI 질문.
- 검색·질문을 보내면 **검색창은 비운다**. 검색어는 요약줄(`정렬 함수 · 3개`)에, 질문은 답변 칸에 남는다. 일반 검색의 서버 오류·시간 초과 시에는 검색어를 입력창에 다시 표시한다. 다시 쓰려면 검색창을 눌러 최근 기록에서 고른다.
- 최근 검색어에서 AI로 물었던 건 앞에 ✦가 붙고, 누르면 다시 AI로 묻는다.
- 처음 열면 검색창 아래에 `?` 규칙 안내가 한 번 뜬다. **알겠어요**를 누르면 다시 안 뜬다.
- 설정 `codeMemory.askOnQuestionMark`(기본 켬)를 끄면 끝의 `?` 규칙과 안내가 꺼지고 Enter는 항상 일반 검색이다. Ctrl+Enter는 계속 AI 질문.
- 규칙 함수(`endsWithQuestionMark`, `looksLikeQuestion`)는 `src/logic.ts`에 있고, 사이드바 화면도 같은 함수를 그대로 쓴다. 단위 테스트로 확인한다.

검색 결과 위에 **AI 답변** 영역이 생긴다. 검색 결과와 따로라서 서로 덮어쓰지 않는다.

| 화면 | 뜻 |
|---|---|
| 생성 중 | 답변을 만드는 중. 그동안 묻기는 잠긴다 (중복 요청 방지). 질문은 검색창에 그대로 남는다 |
| 답변 완료 | 답변 속 **[S1]** 을 누르면 아래 참고 코드 S1 카드가 펼쳐지고 그쪽으로 이동한다. 카드에서 원본 열기·삽입·복사·비교 |
| 근거 부족 | `insufficient_context`. 저장된 코드에서 답할 근거를 못 찾음. **다른 말로 묻기** / **같은 말로 일반 검색** |
| 오류 | 입력 오류(422) / 준비·연결 실패(503) / 시간 초과(504·클라이언트) / 잘못된 인용·미완료(502) / 서버 연결 안 됨. **다시 묻기**는 사람이 누를 때만 보낸다 (자동 재전송 없음) |

- 참고 코드 목록에 없는 인용(예: 답변에 [S9] 이 있는데 sources 에 없음)은 빨갛게 표시하고 열 수 없다. LLM 이 만든 출처를 그대로 믿지 않는다.
- 답변 아래에 모델 이름, 토큰 사용량(입력/출력/합계), 걸린 시간, **전체 DB 대상**을 표시한다. AI 질문은 검색 범위(프로젝트·언어)와 상관없이 전체 DB 를 대상으로 한다.
- 늦게 도착한 이전 질문의 답은 버린다 (질문마다 번호를 붙여 확인).
- 제한 시간은 `codeMemory.askTimeoutSeconds` (기본 45초). 검색 후보 수 `limit`은 `codeMemory.searchLimit`을 같이 쓴다.
- 제목줄의 열쇠 아이콘에서 개인 키와 서버 기본 키를 선택한다. 개인 키는 VS Code SecretStorage에 보관하며 AI 질문에만 전달한다. 자세한 조건은 아래 AI 키 안내와 [사용자 키 가이드](../docs/PERSONAL_LLM_KEYS.md)를 따른다.

### 답변 화면 기능

| 기능 | 동작 |
|---|---|
| 생성 중 취소 | 헤더의 **취소** 또는 Esc. 기다리기만 그만둔다 (서버 쪽 생성은 확장이 멈출 수 없음). 걸린 초가 칩에 보인다 |
| 스트리밍 표시 | 참고 코드 이름이 먼저 뜨고 답변이 이어서 나온다. OpenAI는 답변 조각을 전달하며, Claude·Gemini는 현재 제공자 생성을 마친 뒤 답변 전체를 전달한다. 완료되면 인용 버튼·카드 화면으로 바뀐다 |
| 답변 복사 | 헤더 복사 아이콘(C) → 질문·답변·참고 코드 목록을 마크다운으로 |
| 코드 글씨 · 인용 정리 | 답변 속 백틱 코드는 코드 글씨로. 인용된 코드만 펼치고, 인용 안 된 참고 코드는 한 줄로 접어서 아래로 |
| 👍 / 👎 | 👎 면 이유 칩 + 한 줄 메모(선택). 같은 버튼을 다시 누르면 취소. **아직 서버 API가 없어서 이 PC 에만 저장** → 명령 **Code Memory: AI 피드백 내보내기** 로 JSON 열어서 공유 |
| 이어서 묻기 | 답변 아래 입력칸. 앞 대화(최근 2개)를 같이 보내고 최대 3번까지. **새 대화**로 끊음. 위 검색창에서 물으면 항상 새 대화. 최근 기록에는 안 남는다 |
| 저장된 답변 | 같은 질문(띄어쓰기·대소문자·끝의 ? 무시, 새 대화일 때)이면 AI 를 다시 부르지 않고 저장해 둔 답변을 바로 보여준다. 최근 10개, 모드(mock/서버 주소)별. 최근 기록에 "답변 저장됨". **다시 생성**(R)으로 새로 받기 |
| AI 사용량 | 실제 서버 모드에서 상태 표시줄에 오늘 질문 수 `✦ N`, 툴팁에 토큰 합계. 답변 하단에도 오늘 누적. mock·저장된 답변은 세지 않음. 내 PC 날짜 기준 |
| 애매한 질문 경고 | `함수 ?`처럼 4글자 이하이거나 내용 없는 말만 있으면 보내기 전에 한 번 멈춤. Enter 한 번 더 누르면 보낸다 |
| 선택한 코드로 묻기 | 에디터에서 선택 → 우클릭 **Code Memory: 이 코드에 대해 묻기** → 검색창에 `add 함수 어떻게 동작해 ?` 가 채워진다(보내지는 않음) |

### 저장 전 비밀값 감지

저장하려는 코드에 API 키(sk-…, AKIA…, ghp_…, AIza…, xox…), JWT, 개인 키, 주소 안 비밀번호, `password = "…"` 같은 값이 있으면 확인 창으로 한 번 멈춘다. 에디터의 해당 부분엔 노란 물결이 표시된다.

**가리고 저장**을 고르면 서버로 보내는 코드에서만 `"sk-proj-****"`처럼 가리고, 내 파일은 그대로 둔다. 저장 알림과 저장 기록에 "가림 N"이 남는다. `"****"`, `"<your-key>"`, `${TOKEN}`, `os.environ[...]` 같은 자리표시 값은 비밀값으로 보지 않는다. LLM 은 쓰지 않고 규칙으로만 찾는다. 설정 `codeMemory.secretScan`으로 끌 수 있다.

### 원본이 바뀌었는지

검색 결과와 AI 참고 코드마다 원본 파일을 읽어서 저장한 코드와 비교한다. 줄바꿈(CRLF)과 줄 끝 공백 차이는 같은 걸로 본다.

| 표시 | 뜻 |
|---|---|
| 원본 같음 | 저장 때와 같은 자리에 같은 코드 |
| 위치 이동 | 코드는 같은데 줄이 바뀜. 새 줄 번호를 보여주고 원본 열기도 새 위치로 |
| 원본 바뀜 | 내용이 달라짐. **바뀐 부분 보기**(저장한 코드 ↔ 지금 함수 비교 화면), **지금 내용으로 다시 저장** |
| 원본 위치 연결 | 기억한 원본 위치가 없거나 파일을 찾을 수 없음. 위치를 한 번 연결한 뒤 파일만 열 수 있음 |

다시 저장은 지금 파일의 그 함수를 새로 저장하며 기존 행은 그대로 둔다. 2MB 넘는 파일은 비교하지 않는다.

### 중복 저장 알림 · 다시 볼 만한 코드 · 시연 모드

- **중복 저장 알림**: 저장 직전에 그 코드로 검색을 한 번 한다(LLM 0회). 가장 비슷한 결과의 유사도가 `codeMemory.duplicateThreshold`(기본 0.95) 이상이면 "이미 거의 같은 코드가 저장돼 있어요"를 띄우고 **그래도 저장 / 기존 것 보기 / 취소**를 고른다. 검색이 실패하면 묻지 않고 저장한다. mock 에서는 샘플과 코드가 똑같을 때만 뜬다. `codeMemory.duplicateCheck`로 끈다.
- **다시 볼 만한 코드**: 처음 화면에 저장 기록 중 `codeMemory.reviewAfterDays`(기본 7)일 넘게 지났고, 그 뒤로 검색·원본 열기로 다시 안 본 코드를 3개 보여준다. 누르면 그 함수로 검색한다. **숨기기** 가능. 내 PC 저장 기록만 쓴다.
- **시연 모드**: 명령 **Code Memory: 시연 모드 켜기 / 끄기**(상태 표시줄 메뉴에도 있음). 저장 → 검색 → 범위 → AI 질문 → 원본 바뀜 → 비밀값 가리기 6단계를 띄우고, 실제로 그 기능을 쓰면 자동으로 체크한다. DB 에 샘플을 넣지는 않는다.

### 기록 지우기 · 같은 코드 묶기

- **기록 하나씩 지우기**: 최근 검색, 저장 기록, 다시 볼 만한 코드 줄에 마우스를 올리면 ✕ 가 나온다. 누르면 그 줄만 이 PC 기록에서 빠지고 DB 의 코드는 그대로다. 최근 검색은 ↑↓ 로 고른 뒤 Delete 로도 지운다.
- **같은 코드 묶기**: 검색 결과에서 코드 내용이 똑같은 것(줄바꿈 종류·줄 끝 공백·앞뒤 빈 줄 무시)은 순위가 가장 높은 하나만 보이고 나머지는 "같은 코드 N개 더"로 접는다. 순위 번호는 서버 순위 그대로다. 간단히 보기에서는 `+N`. `codeMemory.groupDuplicates`로 끈다. 평가 화면 숫자에는 영향 없다.

### Code Memory 탭 (공부 · 실행 과정 · AI 대화)

공부, 실행 과정 보기, AI 대화, 개념 지도는 코드 옆에 뜨는 **Code Memory** 탭 하나에서 위쪽 탭으로 바꿔 본다. 사이드바는 검색과 오늘 복습만 남는다. 함수 위 **📘 공부** · **▶ 실행 과정 보기**, 검색 결과의 공부 · 실행 과정, 명령 **Code Memory: Code Memory 탭 열기**로 연다. 탭 오른쪽 위 **⧉ 창으로 떼기**를 누르면 따로 뜬 창이 되고(모니터가 두 개면 옆 화면에 두기 좋다), **📌 VS Code에 붙이기**로 다시 탭이 된다. 마지막에 쓴 방식을 기억한다. 예전처럼 사이드바에서 쓰려면 설정 `codeMemory.studyLocation` 을 `sidebar` 로.

코드를 처음 보는 사람도 따라올 수 있게 쉬운 말로 설명한다.

- **이 코드가 하는 일**: 공부 화면 맨 위에 한 문장 설명 · 일상 비유 · 어디에 쓰는지(`POST /study/plain`)와, 예시 입력값으로 진짜 실행한 결과(`fact(5) → 120`).

- **퀴즈**는 진짜 실행 결과로 보기를 만들고 💡 힌트가 있다. **이상한 값 넣어 보기**는 오류를 쉬운 말로 풀어 준다. 점선 밑줄 낱말(함수 · 입력값 · 리스트 …)에 마우스를 올리면 뜻이 나온다.
- 이름: 이해하기(줄별 설명 · 개념 · 내가 설명해 보기 · 다른 방법과 비교) · 연습하기(퀴즈 · 이상한 값 넣어 보기 · 직접 고쳐 보기 · 틀린 곳 찾기) · 다른 언어로 · 코드 리뷰.

- 실행 과정을 보는 동안 편집기 지금 줄 위에 `◀ 이전 | 다음 ▶ | ■ 멈춤` 이 뜨고 상태 표시줄에도 같은 단추가 있다(F10 이 메뉴에 먹히는 환경에서도 마우스로). 탭 안에서는 → · ← · Space · Esc.

- **이 코드에 쓰인 개념**: Python · JavaScript · TypeScript 코드에서 정해 둔 개념 34개를 줄 단위 패턴으로 찾는다(`src/study.ts`, AI 0회). 개념마다 수준(기초·중급·심화), 설명, 예시, **흔한 오해**, **비슷하지만 다른 것**, 공식 문서(Python 문서·MDN·TypeScript 핸드북), 먼저 알면 좋은 개념. 누르면 그 개념이 쓰인 줄을 강조하고 "처음 봄 / 아는 것"을 표시할 수 있다.

### 편집기에서 따라가기 · 내 PC 에서 직접 실행

- Python 함수 위 **▶ 따라가기**(CodeLens) → 무엇으로 부를지(`even_numbers([3, -4, 0, 7])`) 적으면 공부 화면의 실행 따라가기가 열리고 자동 재생한다. 공부 화면에서 "편집기에서 따라가기"를 켜도 같다.
- 편집기에서 지금 줄을 디버거처럼 강조하고, 줄 끝에 그 순간의 변수 값을 회색 글씨로, 지나간 줄 끝에 실행 횟수(×N)를 붙인다. 상태 표시줄에 진행 상황. **F10** 한 단계, **Esc**(또는 상태 표시줄 클릭) 멈춤. 디버깅 중에는 F10 을 가로채지 않는다.
- Python 코드의 실행 따라가기 · 깨뜨려 보기 · 바꿔 보기 채점은 **이 PC 의 Python 으로 직접 실행**한다(`sys.settrace` 로 줄마다 기록, 400단계·5초 제한). Backend 없이 진짜로 돈다. 처음 실행할 때 확인창(프로젝트별로 "다시 묻지 않기"). Python 은 `python` · `py` · `python3` 순서로 찾고, 못 찾으면 `codeMemory.pythonPath`. `codeMemory.localRun` 을 끄면 서버(`POST /study/trace` · `run`)를 쓴다. JS · TS 는 아직 서버만.
- 검색 결과에서 연 코드는 열린 편집기나 작업 폴더에서 같은 파일을 찾아 따라가고, 못 찾으면 사이드바에서만 보여준다.

### 저장 코드 삭제

결과 카드 오른쪽 끝 **삭제** → 확인창 → `DELETE /snippets/{id}` 로 그 코드 한 개를 DB 에서 지운다(임베딩도 같은 행이라 같이 지워진다). 지우면 검색 결과, 저장 기록, 마지막 검색 복원에서 바로 빠진다. 서버가 404 를 주면 "이미 없음"으로 보고 화면에서만 뺀다. 422(잘못된 ID)·503(삭제 확인 실패)은 이유를 알려준다. 지운 코드를 참고한 저장된 AI 답변은 지우고, 프로젝트·언어 목록은 다시 받는다. 지금은 각자 DB 를 쓰므로 내 DB 에서만 지워지고 팀원 DB 에는 남는다. mock 모드에서는 창을 다시 열 때까지 샘플에서만 빠진다. 일괄 삭제는 아직 없다.

### AI 키 (내 키로 AI 답변 받기)

검색 패널 제목줄의 🔑(또는 상태 표시줄 메뉴의 **AI 키 설정**)으로 연다. OpenAI · Anthropic(Claude) · Google(Gemini) 키를 넣을 수 있고, 붙여넣으면 키 모양으로 회사를 골라준다(바꿀 수 있음).

- 키는 VS Code 비밀 저장소(SecretStorage)에만 저장한다. 설정 파일·Git·화면에는 남지 않고, 화면엔 `sk-proj-…a1b2`처럼 끝 4자리만 보인다.
- **AI 질문(`POST /ask`)에만** 헤더로 보낸다. 검색·저장 요청엔 싣지 않는다.
  ```
  X-LLM-API-Key: <사용자 키>
  X-LLM-Provider: openai | anthropic | google
  ```
  헤더 이름은 `src/logic.ts`의 `LLM_KEY_HEADER`, `LLM_PROVIDER_HEADER` 한 곳에서 바꾼다.
- 서버 주소가 `localhost`/`127.0.0.1`이거나 `https`일 때만 보낸다. 그 밖의 `http` 주소면 키를 빼고 서버 기본 키로 묻고, 답변 아래에 알린다.
- "내 키 / 서버 기본 키" 중 고를 수 있다. 키가 없거나 서버 기본 키를 고르면 지금처럼 서버 `.env` 키를 쓴다. mock 모드에서는 키를 쓰지 않는다.
- 서버가 **401·403**(예: `{"code":"llm_key_invalid"}`)을 주면 "AI 키를 확인하세요"와 **AI 키 설정 열기 / 서버 기본 키로 다시 묻기**를 띄운다. 자동 재전송은 없다.
- 상태 표시줄에 내 키를 쓰는 중이면 🔑가 붙고, 툴팁에 어떤 키인지 나온다.

### 성능 평가 (팀용)

명령 팔레트의 **Code Memory: 평가 실행 (팀용)**으로 연다. 메뉴에는 넣지 않았다.

1. 질문 파일을 고른다. 열린 폴더의 `eval/` 아래 JSON 을 찾아주고, 없으면 **예시 질문 파일 만들기**로 `eval/questions.json`을 만든다.
   ```json
   { "questions": [
     { "id": "Q1", "q": "두 숫자를 더하는 함수", "expected": [12] },
     { "id": "Q2", "q": "JWT 토큰의 서명과 만료를 검증하는 함수", "expected": [] }
   ] }
   ```
   `expected`는 정답 코드의 DB ID 다. 정답이 없는 질문은 `[]`로 두면 "모르는 건 모른다고 하는지"로 따로 센다. 질문마다 `project`, `language`를 넣으면 그 범위로 검색한다.
2. **검색만**(LLM 0회) 또는 **검색 + AI 답변**(질문마다 LLM 1회)을 고른다. 진행 알림에서 취소할 수 있고, 자동 재시도는 없다. AI 평가는 일반 AI 질문과 같은 키 선택을 사용하며 진행·결과에 제공자 또는 서버 기본 키를 표시한다. 개인 키를 전송할 수 없는 서버 주소면 호출 전에 평가를 중단한다. 내보내기에 실제 키는 포함하지 않는다.
3. 결과 탭에 아래 지표가 나온다.

| 화면 이름 | 정식 용어 | 뜻 |
|---|---|---|
| 한 번에 찾음 | Hit@1 | 정답 코드가 1등으로 나온 비율 |
| 3개 안에 찾음 | Hit@3 | 정답 코드가 3등 안에 든 비율 |
| 정답 평균 순위 | Mean rank | 찾은 질문들의 정답 순위 평균 |
| 찾는 데 걸린 시간 | 평균·p95 | `/search` 요청부터 응답까지 |
| AI 답변 평균 토큰 | usage.total_tokens | 제공자가 돌려준 실제 토큰 |
| 모르는 건 모른다고 함 | | 정답 없는 질문에 근거 부족으로 답한 수 |

질문별 표의 줄을 누르면 사이드바에서 그 질문으로 검색한다. **내보내기**로 마크다운 표(포스터·문서), CSV(엑셀), JSON(원자료)을 저장한다. mock 결과는 검색어와 상관없는 샘플이라 숫자에 의미가 없다. 토큰 절감률(기준/개선 비교)은 RAG 쪽 측정 결과를 쓴다.

### 찾기 쉬운 곳

- **우클릭 메뉴 맨 위**: 💾 코드 저장 · ✦ 이 코드에 대해 묻기 · 🔍 비슷한 코드 찾기 · 📘 이 코드로 공부 (선택이 없으면 커서가 있는 함수)
- **함수 위 글자**(CodeLens): `💾 저장 | ✦ AI에게 묻기 | 🔍 비슷한 코드 | 📘 공부` — 선택 없이 그 함수로. 설정 `codeMemory.codeLens` 로 끄기
- **단축키**: Ctrl+Alt+S 저장 · **Ctrl+Alt+A 묻기** · Ctrl+Alt+F 검색창
- **검색 패널 제목줄 아이콘**: 메뉴·모드 / AI 피드백 내보내기 / 시작하기 안내
- **상태 표시줄 Code Memory**: 모드 + 모든 기능(단축키, 👍👎 개수) + 설정이 한 메뉴에
- 👍/👎 를 누르면 옆에 **피드백 모아보기 (JSON)**, 처음 화면에 단축키 안내 카드

답변 칸 단축키 (헤더의 **?** 에도 나옴): `1`~`9` S1~S9 코드로 · `C` 복사 · `R` 다시 생성 · `F` 이어서 묻기 칸 · `Esc` 닫기 / 생성 취소

### 요청·응답

공식 형식과 오류 처리는 [API_CONTRACT.md](../API_CONTRACT.md)를 우선한다. 아래는 Extension 연결에 필요한 요약이다.

```
POST /ask   { "q": "두 숫자를 더하는 함수의 동작을 설명해줘.", "limit": 10 }
200         { status: answered | insufficient_context, answer, sources[{ citation_id, id, 저장 7필드, score }], model, usage }
```

스트리밍·이어서 묻기의 요청과 응답:

```
요청에 추가   "stream": true                         → 한 글자씩
              "history": [{ "q", "answer" }]         → 이어서 묻기 (최근 2개, answer 는 앞 1500자)
응답에 추가   "history_used": 반영한 이전 대화 수      → 없으면 화면에 "서버가 아직 이전 대화를 반영하지 않아요"

stream 응답 (Content-Type: text/event-stream)
  event: sources   data: { "sources": [...] }           참고 코드 먼저 (미리 보기)
  event: delta     data: { "text": "답변 조각" }          여러 번
  event: done      data: { 위 200 응답과 같은 JSON }      최종 확인은 여기서 parseAskResponse
  event: error     data: { "status": 503, "detail": "…" }
서버가 일반 JSON 으로 답하면 한 번에 보여준다. done 없이 끊기면 "답변이 중간에 끊겼습니다"
```

최종 응답 검증은 `src/logic.ts`의 `parseAskResponse`가 담당한다. 계약을 바꿀 때는 Backend·Extension·단위 테스트를 함께 맞춘다. 오래된 Backend 등으로 `/ask`가 없으면(404) "AI 질문 API가 아직 없습니다"로 안내하므로 서버의 브랜치·커밋을 확인한다.

### mock 으로 화면 시험

mock 모드에서는 서버 없이 샘플 답변(참고 코드 S1 add, S2 even_numbers, 인용 안 된 S3 sort_users)이 한 글자씩 나온다. 이어서 묻기도 mock 답변이 따로 있다. 질문에 아래 글자를 넣으면 다른 화면을 볼 수 있다.

| 질문에 넣을 글자 | 화면 |
|---|---|
| `#근거부족` | 근거 부족 (참고 코드 없음, LLM 호출 없음) |
| `#오류` | 503 준비·연결 실패 |

## 시작하기 안내

명령 팔레트의 **Code Memory: 시작하기 안내** 또는 검색 패널 처음 화면의 **처음이면 시작하기 안내 보기**를 누르면 VS Code 시작 화면에 4단계 안내(모드 확인 → 저장 → 검색 → 찾은 코드 쓰기)가 열린다. 각 단계의 버튼을 누르면 완료 표시가 된다.

## 단위 테스트

VS Code 없이 도는 로직(`src/logic.ts`: 정규식 함수 이름 찾기, 함수 고르기, 줄 번호 보정, 들여쓰기 맞추기, 저장 응답 읽기)을 테스트한다.

```powershell
cd C:\dev\capstone-rag\extension
npm.cmd run test:unit
```

`out/` 폴더에 컴파일 결과가 생긴다. 커밋하지 않는다. 저장 응답 검사는 ready·failed, 저장된 ID가 있는 503과 없는 503, 계약에 맞지 않는 응답을 포함한다. [2026-11-05 검증](../docs/INTEGRATION_TEST_2026-11-05.md)에서는 26개 테스트가 통과했다.

## .vsix 패키지 만들기

```powershell
cd C:\dev\capstone-rag\extension
npm.cmd run vsix
```

검사·린트·배포용 빌드 뒤 `code-memory-0.0.1.vsix`가 생긴다. VS Code의 확장 화면 `…` → **VSIX에서 설치**로 설치한다. `publisher`는 `dev-memory-team`(임시)이다. 마켓플레이스에 올리지 않으면 바꿀 필요 없다. `.vsix` 파일은 커밋하지 않는다.

## 오류 확인

| 증상 | 확인할 내용 |
|---|---|
| tsc를 찾을 수 없음 | extension 폴더에서 npm.cmd ci 성공 여부 |
| npm.ps1 실행 정책 오류 | Windows에서는 npm.cmd 사용; 작업 자동화 프로필은 저장소 설정의 cmd.exe 확인 |
| npm ci가 esbuild.exe의 EPERM으로 실패 | 실행 중인 watch·디버그 작업을 먼저 종료한 뒤 재시도 |
| 잘못된 problemMatcher: $esbuild-watch | 권장 esbuild problem matcher 확장 확인 또는 사전 빌드 후 위 명령으로 개발 호스트 실행 |
| 서버 연결 실패 | Backend 실행, apiUrl, Dev Container 8000 포트 전달 확인 |
| 저장 응답 시간 초과 / 저장 여부 확인 필요 | 같은 POST를 반복하지 말고 서버 로그와 DB에서 저장 여부부터 확인 |
| 503 응답에 저장된 ID가 있음 | 원문은 저장됨. 해당 ID의 DB 상태 확인 후 기존 행 재처리 |
| embedding_input_invalid | 원문은 보존됨. 입력 한도와 코드를 확인하고 같은 입력의 반복 재처리 중단 |
| 검색 응답 시간 초과 | 첫 검색은 모델 준비로 오래 걸릴 수 있음. 잠시 후 다시 검색 |
| 첫 검색이 오래 걸림 | Swagger에서 모델 준비와 첫 검색이 끝난 뒤 UI 검색 |
| 결과가 없음 | DB의 검색 가능한 embedding 행이 준비됐는지 확인 |
| 원본 위치 연결 / 원본 파일을 찾을 수 없음 | 원본 프로젝트 위치를 한 번 연결하고 상대 경로의 실제 파일 존재 확인. 다른 PC의 파일은 별도로 준비해야 함 |
| 상태 표시줄이 계속 mock | 설정의 codeMemory.mock 체크 해제 여부 확인 |
| Ctrl+Alt+F가 동작하지 않음 | 다른 프로그램·확장이 같은 단축키를 쓰는지 확인. 명령 팔레트의 Code Memory: 검색창 열기로 대신 실행 |

전체 실행 순서와 자동 Embedding은 [개발 가이드](../docs/DEVELOPMENT.md), 기존 ID 재처리는 [RAG 가이드](../rag/README.md)를 따른다. 실제 확인한 결과는 [2026-11-05 검증 기록](../docs/INTEGRATION_TEST_2026-11-05.md), 이전 수동 벡터 준비 단계의 기록은 [2026-10-28 검증](../docs/INTEGRATION_TEST_2026-10-28.md)에 보존한다.

과거 `scripts/mock_server.py`는 HTTP 201/id만 반환하는 초기 저장 시험 도구다. 현재 API 계약 검증에는 실제 Backend를 사용한다. Extension 설정 mock=true는 이 스크립트를 호출하지 않는 별도의 UI 모의 모드다.
