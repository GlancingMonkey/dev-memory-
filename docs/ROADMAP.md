| 순서 | 작업 | 확인 기준 |
|---|---|---|
| 1 | GET /filters 및 project·language 조건 검색 | 실제 DB의 유효 벡터만 집계, 조건을 적용한 뒤 Top-K, 적용 조건 응답 |
| 2 | Context 동일 코드 중복 제거·예산 선택 | 원문·ID 보존, 대표/제외 출처 기록, 전체 스니펫과 실제 토큰 계수 |
| 3 | 실제 코드·질문 25개 평가 | 검색 20개 정답 질문과 근거 부족 5개를 구분, 같은 조건의 전후 토큰·답변·시간 |
| 4 | 통합 회귀와 근거 자료 정리 | 저장·검색·JSON/SSE 답변·실패·출처 대조, 원본 결과와 실행 조건 보관 |

기존 E5 세 모델 비교는 보존한다. 새 품질 평가의 분모와 환경을 기존 10개 CPU 비교와 섞지 않는다.
이번 비교는 동일한 LLM·지시문·후보·예산에서 Context 선택 정책을 비교한다.
검색 순위, 답변 내용의 정확성, 출처 일치와 토큰 절감은 서로 다른 결과다.

## Database·Extension과 함께 확인

- Database는 공용 데이터와 실제 DB 상태·원문·벡터 보존을 대조한다.
- Extension은 [PR #51](https://github.com/GlancingMonkey/dev-memory-/pull/51)의 검색 범위 UI를 실제 서버와 연결한다.
- 일반 검색과 AI 질문의 범위 표시를 확인한다. 현재 /ask는 전체 DB를 검색하며 /search의 조건을 받지 않는다.
- 답변 본문 [S1] → 참고 코드 → 원본 파일과 줄 범위, 복사·빈 편집기 삽입을 실제 Windows 개발 호스트에서 확인한다.
- 오류·시간 초과·취소·늦은 응답·후속 질문·질문 복구·테마를 실제 화면에서 확인하고 모의 검사와 구분한다.
- Git을 받는 것만으로 다른 PC의 DB 행이나 원본 소스 파일이 생기지는 않는다.
