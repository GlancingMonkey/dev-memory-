## 프로젝트를 다시 열어야 하는 불편 개선

사용자가 다른 프로젝트의 코드 원본을 열 때마다 폴더를 다시 여는 불편을 지적했다.

- 연 프로젝트 위치를 VS Code 로컬 globalState에 기억한다. 로컬·원격 확장 환경은 구분한다.
- 기억한 프로젝트는 현재 작업 영역에 없어도 파일만 연다.
- 예전 코드·이동한 프로젝트는 결과의 ‘원본 위치 연결’에서 폴더를 한 번 선택한다. 작업 영역에 추가하지 않는다.
- 이름이 같은 여러 프로젝트를 임의로 선택하지 않는다. 사용자가 연결한 위치를 우선한다.
- 위치 연결 뒤 검색·AI 참고 코드 카드의 파일 상태를 다시 읽으며 LLM을 재호출하지 않는다.
- 저장 API의 7개 필드·Backend·DB 구조는 바꾸지 않는다. 실제 원본 경로는 서버·DB·Git·설정 파일로 보내지 않는다.

## 오류와 늦은 검색 응답에서 발견한 문제

실제 Backend와 분리한 로컬 시험 서버(18001)를 사용했다. 이 서버의 검색 결과와 점수는 화면 검사용이며 E5 검색 품질이나 실제 LLM 응답으로 집계하지 않는다. DB와 LLM은 호출하지 않는다.

- HTTP 503은 서버 오류로 구분됐지만, 제출한 검색어가 입력창에 남지 않았다. 오류가 났을 때 새로 입력한 내용이 없으면 실패한 검색어를 복원하도록 수정했다.
- alpha 응답을 15초 지연하고 beta로 바꿨다. 요청 로그에서 beta 응답 후 alpha 응답이 도착한 것을 확인했고, 사용자는 창 다시 로드 뒤 alpha 2개로 돌아가는 문제를 확인했다. 웹뷰가 이전 응답을 무시해도 확장 본체가 이전 상태를 저장하는 것이 원인이었다.
- 최신 요청과 현재 뷰의 결과만 화면과 복원 상태에 반영하도록 수정했다. 이전 성공·이전 오류·닫힌 뷰에서 끝난 요청의 자동 회귀 검사 3개는 수정 전 실패, 수정 후 통과했다.
- 수정한 코드의 Windows 빌드는 사용자가 `build finished`로 확인했다. 수정 후 실제 역순 응답(beta 완료 뒤 alpha 완료)에서 다시 로드해도 beta 결과 3개가 유지됐다.
- 같은 시험 서버의 HTTP 503에서 검색어가 입력창에 남는 것을 확인했다. 작업 영역의 검색 제한만 2초로 낮추고 12초 늦은 응답을 보내자 시간 초과 안내와 검색어 보존도 확인했다. 시험 뒤 검색 제한을 20초로 되돌렸다.
- AI 시험 응답을 종료하지 않자 30초 뒤 ‘응답 시간 초과’가 표시됐다. 이후 대기 제한을 120초로 늘리고 사용자가 생성 중 취소 버튼을 누르자 ‘취소함’으로 바뀌었다. 서버 로그에서도 약 6.24초 만에 완료 전 연결 종료를 확인했다. 이는 Extension의 기다리기 취소 확인이며, 실제 제공자의 생성 중단이나 과금 중단 검증은 아니다.
- 시험 서버를 정상 모드로 바꾼 뒤 ‘복구 확인’을 일반 검색하자 beta 결과 3개로 복구됐다.
- 결과의 ‘검색 기록 복사’를 새 빈 편집기에 붙여넣어 ‘복구 확인’ 질문·db-check-beta 범위·결과 3개가 일치함을 확인했다.
- 최근 검색에서 ‘시간 초과 확인’을 다시 선택하자 요약 질문이 바뀌고 beta 범위와 결과 3개는 유지됐다. 앞서 확인한 역순 응답 뒤 재로드와 함께 질문·조건·결과의 일치를 대조했다.
- 시험 워크스페이스에서 원래 mvp-auto-test-1104 폴더로 돌아간 뒤, 실제 Backend(8000)에 ‘0으로 나누는 경우를 처리하는 함수’와 해당 프로젝트 조건으로 GET /search가 전달되고 HTTP 200이 반환됐다. 사용자는 safe_divide가 검색됨을 확인했다. 시험 창의 설정을 실제 서버 설정과 혼동하지 않도록 분리했다.
